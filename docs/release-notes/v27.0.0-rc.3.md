The tag `v27.0.0-rc.3` is created for this exact commit and image after the documentation has
been reviewed. It is the first release candidate tag of driftsniff CE; there is no earlier release.

tagged, and both review copies are superseded; the [v27.0.0-rc.1](v27.0.0-rc.1.md) and

## Changed in the documentation since v27.0.0-rc.2

- The push example in the API guide, the admin guide, tutorial 3 and `push.md` used the resource
  `networks` with the fields `_id`, `name` and `vlan`. Posted to a push source, that example is
  refused with HTTP 422 `bad_object`. It now uses the UniFi resource `unifi-networks` with the
  fields `id`, `name` and `vlanId`, which Development accepts (HTTP 200, change created).
- The admin guide and tutorial 3 say that a declared resource needs a type table and its key field
  `id`, and that the hint under the push form of this build still shows the older example.
- The documentation index names the screenshot folder in words instead of linking to a folder.

## What is in it

- **Collection.** UniFi Network and Xen Orchestra sources read on a schedule (1 to 60 minutes) with
  read-only credentials, four TLS modes and a read-only test connection. Push sources take a
  configuration from a sender with a per-source key.
- **Change detection.** Each reading is redacted, normalised and compared with the one before.
  Only differences are stored. Secrets are kept as keyed fingerprints. Each item is rated low,
  medium, high or critical by a named rule with its reason.
- **Web interface.** Dashboard with stat cards, open items by severity, Needs attention, drift
  lines, a 30 day trend, breakdowns and an activity timeline; the change list with filters, sort
  and mutes; the change detail with before and after, rules, acknowledgements, notes and external
  analysis; sources with change replay and coverage; history and configuration; settings. Light
  and dark themes, layouts from 390 to 1440 px, keyboard operation.
- **Access.** Viewer, operator and admin roles; first-admin setup with a one-time code; sign-in
  limits and locks; API tokens with read and enrich scopes.
- **Integrations.** `/api/v1` to read changes and attach external analysis; one notification
  channel (signed webhook or SMTP).
- **Operations.** Health route, online backup with integrity check, nightly retention (30 to 365
  days), hardened container, audit events for every admin action.

## Known limits

- The UniFi and Xen Orchestra field names have not been checked against a lab controller (see
  [vendor-notes/unifi.md](../vendor-notes/unifi.md) and [vendor-notes/xo.md](../vendor-notes/xo.md)).
  Treat the results on a real controller as unverified until that check is done.
- The hint under the push form still shows the example `networks: _id, name, vlan`. The form
  text is part of the application and is not changed by this documentation candidate.
- A user's role cannot be changed and a password cannot be reset from the interface; a locked user
  is unlocked by itself after 15 minutes.
- No bulk acknowledge and no CSV export of changes.
- A nightly retention run that is missed while the application is stopped is not made up.
- One notification channel per installation.
